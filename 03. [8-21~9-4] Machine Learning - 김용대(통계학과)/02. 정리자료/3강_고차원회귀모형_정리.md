## §1. 고차원 회귀모형이 왜 필요한가 `P.3~P.13`

### 1-1. 문제 정의 `P.4`
- **고차원(高次元) 회귀모형** = 설명변수 개수 `p`가 데이터 개수 `n`보다 많은 경우 (`p > n`)
- 이럴 때 두 가지 문제가 생겨:
  1. **다중공선성**: 설명변수들끼리 서로 너무 비슷해서(상관관계가 높아서), "최소제곱추정량"(회귀계수를 구하는 표준적인 방법)이 하나로 딱 정해지지 않음
  2. **과대적합(overfitting)**: 변수가 너무 많으면 모델이 훈련 데이터에만 억지로 맞춰지고, 새로운 데이터에는 예측을 잘 못함

> 💡 **비유**: 미지수가 5개인데 방정식이 3개뿐이면 답이 하나로 안 정해지는 것과 같아. 여기서도 "정보(데이터)"보다 "구해야 할 것(변수)"이 많아서 문제가 생기는 거야.

### 1-2. 실제 사례 4가지 `P.5~P.13`

**(1) 이미지 분석 (잡음 제거) — `P.5~P.8`**
- 사진 한 장 = 픽셀 수만큼의 숫자 데이터 (예: 640×480 컬러사진이면 변수가 약 92만 개!)
- 모형: `관측된 픽셀값(y) = 원본 픽셀값(β) + 잡음(ε)`
- 목표: 잡음 낀 사진(y)을 보고 원본(β)을 추정 → 이게 바로 "회귀"의 일종
- `P.8`에서 벌점화 방법(Lasso, Fusion)으로 잡음을 제거한 결과 사진을 보여줌

**(2) 브레인 네트워크 분석 — `P.9~P.10`**
- 뇌의 여러 지역 각각의 혈류량을 변수로 놓고, 어떤 지역과 어떤 지역이 서로 연관돼 있는지(편상관계수)를 분석
- 지역 수가 많아지면 역시 변수가 데이터보다 많아지는 고차원 문제가 됨

**(3) SNS 이용 신용평가 — `P.11~P.12`**
- SNS 글에 쓴 단어 하나하나를 변수로 사용 (텍스트마이닝)
- 사용 가능한 단어 수는 사실상 무한 → 변수의 대부분이 0 (=sparse, 희소하다)
- 신용평가에 진짜로 영향 주는 단어는 소수일 것이라 예상

**(4) Feature Learning — `P.13`**
- 원본 데이터를 비선형 변환(다항식, 푸리에 변환, 커널, 딥러닝 등)해서 "특성(feature)"을 만들고, 그 특성들을 입력변수로 사용
- 이 특성들의 차원이 매우 커서 고차원 회귀 기법이 꼭 필요해짐

### 벌점화(Penalization)라는 공통 해법 `P.15`
네 가지 사례 모두 결국 아래 형태의 문제로 귀결돼:

```
최소화할 값 = (예측오차)² 의 합  +  벌점항(J_λ)
```

- 그냥 오차만 최소화하면 위에서 말한 문제(공선성, 과적합)가 생기니까
- **벌점항**을 추가해서 회귀계수(β)가 너무 커지지 않도록 억제함
- `λ`(람다)는 "**조율모수**": 벌점을 얼마나 강하게 줄지 정하는 값 (0이면 그냥 일반 회귀와 같음)

## §2. 능형회귀 (Ridge Regression) `P.14~P.21`

### 2-1. 기본 아이디어 `P.16~P.17`
- 일반 최소제곱추정량: `β̂ = (XᵀX)⁻¹ Xᵀy`
- 문제: `p > n`이면 `XᵀX`의 역행렬이 존재하지 않음 → 계산 자체가 불가능
- **해결책**: 벌점함수로 `J_λ(β) = λβ²` (제곱, 그래서 **L2 벌점**이라 부름)를 추가

```
능형 추정량:  β̂_ridge = (XᵀX + λI)⁻¹ Xᵀy
```

- `λI`를 더해줘서 역행렬이 항상 존재하게 만드는 게 핵심 트릭이야.

### 2-2. "축소추정량"이라는 성질 `P.18~P.19`
- 변수들끼리 독립이라면: `능형회귀 추정량 = a × 최소제곱추정량` (단, `a < 1`)
- 즉 원래 추정값을 **0 쪽으로 살짝 줄여서(축소, shrink)** 사용하는 것
- 왜 줄이는 게 더 좋을까? → **James-Stein 추정량**이라는 통계학의 유명한 결과 때문
  - 1~2차원에서는 그냥 표본평균이 최선이지만
  - **3차원 이상**에서는 표본평균을 줄여주는(축소하는) 추정량이 오히려 더 정확함
  - 능형회귀는 이 아이디어를 회귀계수 추정에 적용한 것

> 💡 직관: 데이터에는 잡음이 섞여 있으니, 추정값을 극단으로 밀어붙이기보다 살짝 보수적으로(0 쪽으로) 당겨주면 전체적으로 예측이 더 안정적이 된다는 뜻이야.

### 2-3. 실제 계수 비교표 `P.20`
| Term | LS(일반회귀) | Selection(변수선택) | Ridge |
|---|---|---|---|
| x1 | 0.680 | 0.740 | 0.389 |
| ... | ... | ... | ... |
| **Test Error** | 0.586 | 0.574 | **0.540** |

→ Ridge가 예측오차(Test Error)를 가장 낮춤. 단, 계수를 보면 **어떤 것도 정확히 0이 되지 않음** (모든 변수를 조금씩 다 사용).

### 2-4. 능형회귀의 한계 `P.21`
- 계수가 하나도 0이 안 되니까, 변수가 많을 때 **해석이 어렵고 과적합 위험이 남음**
- "필요없는 변수는 아예 빼주는(0으로 만드는)" 기능이 있으면 좋겠다 → **다음 절: 라쏘(LASSO)**

## §3. 라쏘회귀 (LASSO) `P.22~P.27`

### 3-1. 정의 `P.23`
- 벌점함수를 절댓값으로 바꿈: `J_λ(β) = λ|β|` (**L1 벌점**)

```
라쏘 추정량:  β̂_lasso = argmin  Σ(y-Xβ)² + λ Σ|β_j|
```

- 핵심 성질: **회귀계수 중 몇 개가 정확히 0으로 추정됨** → 모델이 sparse(희소)해짐
- 즉 라쏘는 "변수 선택" 기능을 자동으로 갖고 있는 것!

### 3-2. 왜 하필 라쏘만 계수가 정확히 0이 될까? `P.24~P.25`
같은 문제를 아래처럼 "제약식이 있는 최적화 문제"로 바꿔 쓸 수 있어:

- 능형: `오차² 최소화, 단 Σβ² < s`  (제약 영역이 **원(구)** 모양)
- 라쏘: `오차² 최소화, 단 Σ|β| < s`  (제약 영역이 **마름모(다이아몬드)** 모양)

`P.25`의 그림이 핵심이야:
- 마름모는 **꼭짓점**이 축(β1=0 또는 β2=0인 지점)에 있음
- 오차를 최소화하는 타원이 이 마름모와 만날 때, **꼭짓점에서 만날 확률이 높음** → 그래서 계수 중 일부가 정확히 0이 됨
- 반면 원은 꼭짓점이 없어서 축 위에서 딱 만날 이유가 없음 → 계수가 0이 잘 안 됨

> 💡 이게 라쏘가 sparse한 이유를 설명하는 가장 유명한 기하학적 그림이니, `P.25`의 마름모 vs 원 그림은 꼭 눈으로 확인해봐.

### 3-3. 실제 계수 비교표 `P.26`
LS / Ridge / Lasso 세 방법의 계수를 나란히 비교 — 라쏘만 x3, x6 계수가 **완전히 빈칸(=0)** 인 걸 확인할 수 있어. Test Error도 라쏘가 가장 낮음(0.491).

### 3-4. λ(조율모수)는 어떻게 정하나 — 교차확인법 `P.27`
1. 데이터를 k개 조각으로 나눔
2. 후보 λ 값마다: (k-1)개 조각으로 모델을 학습 → 나머지 1개 조각으로 예측오차 확인, 이걸 k번 반복
3. k번의 오차를 평균 낸 값이 가장 작은 λ를 최종 선택

→ 이게 바로 **k-fold Cross-Validation**이고, 실무에서 λ 고를 때 표준적으로 쓰는 방법이야.

## §4. 변수선택 vs Ridge vs Lasso 종합 비교 `P.28~P.31`

- `P.29`: 전통적인 "변수선택(all subset selection)" 방법 — 가능한 모든 변수 조합을 다 시도해서 최적 조합을 찾음 (변수가 많으면 계산량 폭발)
- `P.30`: 변수선택과 Ridge의 교차확인 오차 곡선을 나란히 비교
- `P.31`: **Solution Path** 그림 — λ(또는 s)를 바꿔가며 각 계수가 어떻게 변하는지 보여줌
  - Ridge: 계수들이 부드럽게 0 쪽으로 줄어들지만 **정확히 0에 닿지 않음**
  - Lasso: 계수들이 **하나씩 정확히 0에 도달**하며 사라짐 (선이 축에 닿는 게 보임)

이 두 그림의 차이가 §2, §3에서 배운 내용의 결론이야.

## §5. Elastic Net `P.32~P.34`

### 5-1. 왜 필요한가 (동기) `P.33`
- 라쏘는 변수 선택을 잘 하지만, **상관관계가 높은 변수들이 있으면 잘 작동하지 않음**
- 예시 (P.33): 진짜 원인은 F 하나인데, 관측된 변수는 `X1 = F+ξ1`, `X2 = F+ξ2`로 서로 매우 비슷한 두 개
  - 이 경우 이론적으로 최적의 계수는 `(β1, β2) = (1/2, 1/2)` — 즉 **둘을 반씩 나눠 쓰는 게 정답**
  - 하지만 라쏘는 "선택"을 하려는 경향 때문에 둘 중 하나만 쓰고 하나는 0으로 만들어버리는 경우가 많음 → 비효율적

### 5-2. Elastic Net 정의 `P.34`
L1 벌점(라쏘)과 L2 벌점(능형)을 **동시에** 사용:

```
β̂_elastic = argmin Σ(y-Xβ)² + λ1·Σ|β_j| + λ2·Σβ_j²
```

- 조율모수가 2개(`λ1`, `λ2`)라서 계산은 더 복잡함
- `λ1`(라쏘 부분) → 모델이 얼마나 sparse해질지 결정
- `λ2`(능형 부분) → 서로 상관 높은 변수들을 얼마나 "같이 묶어서" 쓸지 결정
- 실무에서 예측 성능이 매우 좋다고 알려져 있음 (라쏘 + 능형의 장점을 합침)

## §6. Fused Lasso — 이미지 디노이징 `P.35~P.38`

### 6-1. 모형 `P.37`
```
Y_ij = β_ij + ε_ij
```
- `Y_ij`: (i,j) 위치 픽셀의 **관측값** (잡음이 낀 값)
- `β_ij`: (i,j) 위치 픽셀의 **실제값** (우리가 추정하고 싶은 것)
- `ε_ij`: 그 픽셀에 섞인 잡음

### 6-2. 추정 방법 (Fused Lasso) `P.38`

```
최소화:  Σ(Y_ij - β_ij)²  +  λ Σ Σ_(k,l)∈N(i,j) |β_ij - β_kl|
```

- 앞부분은 평소처럼 "관측값과 예측값의 차이"를 최소화
- 뒷부분(벌점항)이 핵심: **이웃한 픽셀들(N(i,j))끼리 값 차이가 작도록** 강제함
  - 사진은 보통 이웃 픽셀끼리 색이 비슷하니까(경계선 제외), 이 성질을 이용해서 잡음을 제거하는 것
- 이게 §3에서 배운 라쏘(절댓값 벌점)를 "인접한 값들의 차이"에 적용한 버전이라서 이름이 **Fused(융합) Lasso**야

### 6-3. 결과 비교 `P.8` (앞부분 이미지 예시)
- lasso denoising vs fusion denoising 결과 사진을 비교하면, Fused Lasso가 경계는 유지하면서 잡음은 부드럽게 제거하는 걸 볼 수 있어.

## 한눈에 보는 핵심 정리표

| 방법 | 벌점함수 | 계수가 0이 되나? | 언제 쓰면 좋은가 |
|---|---|---|---|
| **능형회귀 (Ridge)** | `λΣβ²` (L2) | ❌ 안 됨 (다 살아있음) | 변수들끼리 상관관계가 높을 때, 예측력 위주 |
| **라쏘 (Lasso)** | `λΣ\|β\|` (L1) | ✅ 됨 (자동 변수선택) | 실제로 영향 있는 변수만 골라내고 싶을 때 |
| **Elastic Net** | L1 + L2 둘 다 | ✅ 됨 (일부) | 라쏘가 상관 높은 변수를 잘 못 고를 때 |
| **Fused Lasso** | 이웃 값 차이에 L1 | ✅ 됨 (이웃끼리 뭉침) | 이미지처럼 "이웃끼리 비슷해야" 하는 데이터 |
